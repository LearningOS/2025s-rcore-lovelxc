# 总结

实现三个系统调用。对于 fstat 系统调用，需要对 File 的 trait 添加一个 stat 的接口，因为只靠 fd 无法获取文件名，也就无法获取 inode，只能通过 File 的实例来做了。还需要对 DiskInode 类型增加一个 `links_count` 字段 (记得减少 `direct` 的数组大小，保持 128 字节数)。对于 OSInode 类型，调用 inner 的 inode 的 `get_stat` 方法就行。

对于 unlinkat 和 linkat，需要对目标 DiskInode 的 links\_count 进行增加或减少，然后修改对应的目录项。
如果 unlinkat 的文件是只有一个 hard link 的，那么需要调用 Inode 的 clear 方法回收空间。

# 问答题

root inode 能够让我们获取到根目录下的所有信息，同时可以调用 Inode 的相关方法进行文件的创建，查找等功能。
如果 root inode 中的内容损坏了，也就是 DiskInode 内容损坏，我们就可能无法正确的找到根目录下的文件或者写入相关信息，因为可能已经找不到对应的索引 inode。
